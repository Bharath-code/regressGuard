## The 10x thesis

Today's value prop: "know what broke before you commit." The 10x version:

> **The agent fixes what it broke before you ever see it — and can prove it.**

10x = (deterministic detection with zero false positives) × (machine-actionable findings
that drive self-repair) × (zero-step installation inside the agent's own loop). Every item
below serves one of those three multipliers.

---

## Phase 1 — Trust (make detection honest)

### 1.1 [T] Per-test failure identity — ✅ DONE 2026-07-05
The #1 credibility hole: failures compared by count, so "break A while fixing B" is invisible.
**Implementation:** `TestResult.FailedTests` (runner parses `✕/✗/×` jest/vitest/bun markers
+ `--- FAIL:` go test, deduped); `snapshot.TestSummary.FailedNames` (optional,
`omitempty`); `diff.go newNamedFailures` compares identity first, falls back to count.
**Acceptance criteria:**
- [x] Runner captures failing test *names* (vitest/jest/bun/go output) into the snapshot.
- [x] `rg check` flags CRITICAL when a test not failing at baseline is now failing, even
      if the net failed count is unchanged or lower
      (`TestDiffSnapshots_newNamedFailure_sameCount_critical`).
- [x] A test failing at baseline that still fails does NOT produce a new finding
      (`TestDiffSnapshots_sameNamedFailures_noFinding`).
- [x] Graceful degradation: names unparsed → count comparison exactly as today
      (`TestDiffSnapshots_countIncrease_namesUnparsed_stillCritical`).
- [x] Finding names the newly failing test(s) — carried in `CheckResult.Message`, which
      flows unchanged into CLI, `--json`, and MCP payloads.
- [x] Old snapshots (failures but no names recorded) keep count-based behavior; no
      migration (`TestDiffSnapshots_oldSnapshotNoNames_fallsBackToCount`).
- [x] `go test ./...` green; README Known-limitations entry updated.

### 1.2 [T] Array schema beyond first element
**Acceptance criteria:**
- [ ] Normalizer merges the shapes of up to N (e.g. 10) array elements into a union shape;
      heterogeneous arrays produce a stable, deterministic hash.
- [ ] Existing homogeneous-array snapshots produce the SAME hash as today (no baseline
      invalidation / false positives on upgrade) — test asserts this.
- [ ] New test: element[3] drops a field → schema change detected.

## Phase 2 — Wow (the holy-sh*t moments)

### 2.1 [W] Self-healing findings: every CRITICAL ships a repair hint — ✅ DONE 2026-07-05
The demo moment: agent breaks the API → `check` returns not just "role removed from
GET /api/users" but *where to look* → agent fixes it → `check` green → agent reports
"I broke it, I fixed it, here's proof." No human involved.
**Implementation:** `CheckFinding.Hint` populated for CRITICAL findings via
`hintForFinding` (route path-segment match against changed-since-snapshot files, full-list
fallback); flows into `--json` and MCP unchanged. Demo: `demo/demo.sh` (runnable) +
`demo/demo.tape` (vhs) → `demo/demo.gif`, embedded in README; verified end-to-end against
`fixtures/nextjs-app` (hint resolved 5 changed files to exactly the culprit).
**Acceptance criteria:**
- [x] Each CRITICAL finding in `--json`/MCP carries `hint`: changed-files-since-snapshot
      filtered to files plausibly related to the route (path-segment match), falling back
      to full changed list (`TestHintForFinding_*`, 4 tests).
- [x] `docs/json-contract.md` documents the field as additive/optional/best-effort.
- [x] Recorded end-to-end demo GIF of break→detect→fix→green in README
      (`demo/demo.gif`, reproducible via `./demo/demo.sh`).

### 2.2 [W] `rg check` proof-of-verification line
Trust artifact for PRs: one copy-pasteable line proving the check ran against a signed baseline.
**Acceptance criteria:**
- [ ] On pass, print `Verified against baseline <short-hmac> (recorded <age>) — 6 routes, 42 tests`.
- [ ] `rg check --badge` (or in `--json`) emits a markdown-ready line agents can paste
      into PR descriptions.
- [ ] No new dependencies; works in non-TTY.

### 2.3 [W] Zero-config first run (`rg` in an uninitialized repo)
Friction killer: running bare `rg check` with no config should not error — it should offer
the whole flow.
**Acceptance criteria:**
- [ ] `rg check`/`rg snapshot` with no `.regressguard/` runs auto-detection (existing
      `init` logic), shows what it found, and proceeds after a single confirm (or `--yes`).
- [ ] Time from `curl install` to first successful `check` on the demo fixture < 90s,
      measured and stated in README.
- [ ] Non-interactive contexts (CI, MCP) get a structured "not initialized" error with the
      exact command to fix — never a stack trace.

## UI/UX standard (applies to every phase)

- Calm by default (done): no animation unless `--celebrate`; instant render.
- Every error message: what failed → why → the exact next command. Never a bare error.
- One-viewport rule: default output of any command fits 80×24.
- Machine surface (`--json`/MCP) is a versioned contract; humans get prose, agents get
  structure, both from the same engine.

## Engineering standard (elite-bar, enforced not aspirational)

- TDD for every behavior change; `go test ./...` green; slow tests behind `-short`.
- Zero new runtime dependencies without written justification in the PR.
- Any change to normalizer/diff (the trust core) requires a regression test proving old
  baselines still hash identically.
- Backwards compatibility of snapshot format: new fields optional, old snapshots readable.

## Explicit non-goals

Dashboards · visual regression · AI-generated tests · traffic record/replay ·
LLM-in-the-loop judging. These either belong to competitors' moats or dilute the
deterministic-trust position.
